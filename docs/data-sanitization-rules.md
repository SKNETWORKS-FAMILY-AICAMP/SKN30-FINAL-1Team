# 개발·데모 데이터 변형 규칙

## 목적과 저장 위치

- 원본의 표 구조, 문서 형식, 업무 흐름, 계약 상태, 매출 패턴, 제품군과 설명은 유지한다.
- 원본 파일은 수정·이동·삭제하지 않는다.
- XLS, XLSX, CSV 등 표 형식 파일은 `data/sample/`에 저장한다.
- DOCX, PDF 등 문서 파일은 `data/sanitized_docs/`에 저장한다.
- `data/raw/` 원본은 Git에 포함하지 않는다.

## 최소 변경 원칙

- 실제 이름, 거래처명, 연락처, 이메일, 상세주소, 사업자등록번호, 실제 계좌정보, 실제 모델명, 실제 금액처럼 식별 또는 영업기밀 가능성이 있는 값만 가상 값으로 변경한다.
- 일반 제품군명, 영문 제품명, 문서 제목, 계약 조항, 수량 단위, 일반 설명은 그대로 둔다.
- 이미 명백한 테스트·가상 데이터는 다시 바꾸지 않는다.
- 변경이 불확실하면 삭제하거나 추정하지 말고 `[확인필요]`로 표시한다.

## 일관성

- 같은 사람·회사·병원·거래처·주소·실제 모델명은 이번 작업 범위의 모든 파일에서 동일한 가상 값으로 유지한다.
- 직급과 역할, 기관 유형은 유지한다.
- 파일명에 회사명·고객명·날짜가 있으면 본문 변환 결과와 일치시킨다.
- 원본값과 변환값의 대응표는 결과물, Git, README, 최종 응답에 남기지 않는다.

## 값별 처리

- 사람·기관명: 자연스러운 가상 이름으로 변경한다.
- 전화·팩스: 원본 일부 숫자를 재사용하지 않는 테스트 번호로 변경한다. 같은 대상은 같은 번호를 쓴다.
- 이메일: `example.invalid` 도메인을 사용한다.
- 주소: 시·도와 시·군·구는 유지 가능하며, 상세 도로명·건물번호·층·호수는 가상화한다.
- 생년월일: 삭제 대신 가상 생년월일로 변경한다. 업무상 연령대가 중요하면 대략적인 연령대만 유지한다.
- 날짜: 계약·미팅·발주·납품 등의 순서와 간격을 유지하며, 동일 건은 같은 일수만큼 7~30일 이동한다.
- 금액: 필요할 때만 약 ±5~10% 범위에서 조정하고, 합계와 수량×단가 관계를 맞춘다.
- 제품: 일반 제품군명은 유지하고 실제 고유 모델 코드만 가상 모델명으로 변경한다.
- 주민등록번호, 실제 계좌번호, 카드번호, 비밀번호, 인증정보, 서명·도장 이미지, 환자 개인정보는 제거한다. 문서 흐름상 표기가 필요할 때만 `[삭제]`를 사용한다.
- 사업자등록번호·계약번호·발주번호는 화면 시연에 필요하면 가상 번호로 변경한다.

## 숫자값 오인 방지

- 숫자와 하이픈만으로 계좌번호라고 판단하거나 삭제하지 않는다.
- `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/MM/DD` 형식은 날짜로 처리하며 계좌번호로 바꾸지 않는다.
- 계약번호, 발주번호, 세금계산서번호, 우편번호, 제품 코드, 수량, 금액, 사업자등록번호도 숫자 모양만으로 계좌번호로 분류하지 않는다.
- 계좌번호는 `계좌`, `은행`, `예금주`, `입금`, `송금` 등의 주변 문맥 또는 은행명과 번호 조합이 있을 때만 처리한다.

## 파일별 보존 규칙

- XLS/XLSX: 모든 시트(숨김·매우 숨김 포함), 시트 순서·상태, 표, 셀 병합, 서식, 열 너비, 행 높이, 정상 수식을 유지한다.
- DOCX/PDF: 문단, 표, 제목, 페이지 구성과 기본 서식을 유지하고 메타데이터의 식별정보도 확인한다.

## 완료 전 검증

- 실제 식별정보가 남았는지 확인한다.
- 날짜·계약번호·발주번호가 계좌번호 등으로 오인되어 변경되지 않았는지 확인한다.
- 여러 파일의 가상 값이 일관되는지 확인한다.
- 파일명과 본문이 일치하는지, 표·시트·문서 구조가 유지되는지 확인한다.
- 최종 응답에는 생성 파일 경로, 변경 항목 종류·개수, 검증 결과, 원본 미수정 사실만 간단히 작성한다.
